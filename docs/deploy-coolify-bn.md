## ১. ডোমেইন ও DNS

১. ডোমেইন কিনুন (Namecheap / Porkbun / GoDaddy — যেকোনোটা)।
২. Cloudflare-এ সাইটটি যোগ করুন, Cloudflare যে দুটো nameserver দেবে সেগুলো
ডোমেইন রেজিস্ট্রারে বসিয়ে দিন। প্রোপাগেট হতে কয়েক ঘণ্টা লাগতে পারে।
৩. Cloudflare → DNS-এ দুটো রেকর্ড বানান:

| Type | Name  | Content   | Proxy status                    |
| ---- | ----- | --------- | ------------------------------- |
| A    | `@`   | VPS-এর IP | **DNS only (ধূসর মেঘ)** — আপাতত |
| A    | `www` | VPS-এর IP | **DNS only (ধূসর মেঘ)** — আপাতত |

> ⚠️ **এখনই কমলা মেঘ (Proxied) করবেন না।** Coolify-কে Let's Encrypt থেকে SSL
> সার্টিফিকেট আনতে হবে, আর Cloudflare প্রক্সি চালু থাকলে সেটা আটকে যায়। ধাপ ৯-এ
> সার্টিফিকেট আসার পর কমলা করবেন।

## ২. Coolify-তে PostgreSQL সার্ভিস

১. Coolify → **Projects** → নতুন প্রজেক্ট বানান (নাম: `MUTI`)।
২. ভেতরে **+ New Resource** → **Databases** → **PostgreSQL** → ভার্সন **16**।
৩. নাম দিন `muti-db`, **Deploy** চাপুন।
৪. ডিপ্লয় হয়ে গেলে ঐ ডাটাবেসের পেজে **Postgres URL (internal)** লেখা একটা
কানেকশন স্ট্রিং দেখাবে। এটা **কপি করে রাখুন** — পরের ধাপে লাগবে। দেখতে এমন:

```
postgres://postgres:xxxxxxxxxxxx@abcdefgh:5432/postgres
```

> **"internal" স্ট্রিংটাই নিন, "external" নয়।** ইন্টারনাল মানে ডাটাবেস শুধু
> সার্ভারের ভেতর থেকে অ্যাক্সেসযোগ্য — ইন্টারনেটে খোলা থাকে না। ডাটাবেস কখনোই
> পাবলিকলি খুলবেন না।

## ৪. Environment variables

অ্যাপের **Environment Variables** ট্যাবে গিয়ে নিচেরগুলো যোগ করুন:

| Variable               | মান                                                  | Build Variable? |
| ---------------------- | ---------------------------------------------------- | --------------- |
| `DATABASE_URL`         | ধাপ ২-এর internal URL, শেষে `?schema=public` যোগ করে | না              |
| `AUTH_SECRET`          | `openssl rand -base64 32` চালিয়ে যা আসে             | না              |
| `AUTH_URL`             | `https://mutibd.com`                                 | না              |
| `NEXT_PUBLIC_SITE_URL` | `https://mutibd.com`                                 | **✅ হ্যাঁ**    |
| `ADMIN_EMAIL`          | `mymensinghultrasound@gmail.com`                     | না              |
| `ADMIN_PASSWORD`       | শক্ত একটা পাসওয়ার্ড (প্রথম লগইনের পর বদলাবেন)       | না              |
| `UPLOAD_DIR`           | `/app/uploads`                                       | না              |
| `SMTP_HOST`            | `smtp.gmail.com`                                     | না              |
| `SMTP_PORT`            | `587`                                                | না              |
| `SMTP_USER`            | `mymensinghultrasound@gmail.com`                     | না              |
| `SMTP_PASS`            | Gmail App Password (১৬ অক্ষর)                        | না              |
| `NOTIFY_EMAIL`         | `mymensinghultrasound@gmail.com`                     | না              |

### গুরুত্বপূর্ণ তিনটা কথা

- **`NEXT_PUBLIC_SITE_URL`-এর পাশে "Build Variable?" চেকবক্সটা অবশ্যই টিক দিতে
  হবে।** এই মানটা বিল্ডের সময় কোডের ভেতর বসে যায়। টিক না দিলে সাইটম্যাপ, canonical
  URL আর সোশ্যাল শেয়ারের ছবিতে `localhost:3000` চলে যাবে — আর সেটা ঠিক করতে
  পুরো রি-বিল্ড লাগবে।
- **`AUTH_SECRET` কখনো `.env.example`-এর `change-me` রাখবেন না।** এটা দিয়েই
  অ্যাডমিন সেশন সাইন করা হয়। কেউ জেনে গেলে অ্যাডমিন প্যানেলে ঢুকে যেতে পারবে।
- URL-এর শেষে **স্ল্যাশ দেবেন না** — `https://mutibd.com/` নয়, `https://mutibd.com`।

## ৫. ফাইল স্টোরেজ: Cloudflare R2 (সুপারিশ) অথবা volume

অ্যাডমিন থেকে আপলোড করা প্রতিটি ছবি ও PDF কোথাও রাখতে হবে। দুটি পথ — **একটি বেছে নিন**:

### ৫ক. Cloudflare R2 (সুপারিশ)

ফাইল সার্ভারের বাইরে থাকে; redeploy, সার্ভার বদল, ভলিউম ভুল — কিছুতেই হারায় না।
ফ্রি টিয়ার (১০ GB, egress ফ্রি) এই সাইটের জন্য যথেষ্ট।

১. Cloudflare ড্যাশবোর্ড → **R2 Object Storage** → **Create bucket** → নাম `muti-uploads`,
লোকেশন APAC। পাবলিক অ্যাক্সেস চালু করতে হবে **না** — সাইট নিজেই `/uploads/…` দিয়ে
ফাইল সার্ভ করে।
২. R2 পাতায় **Manage R2 API Tokens** → **Create API token** → Permission **Object Read &
Write**, Specify bucket → `muti-uploads` → Create। **Access Key ID** ও **Secret Access
Key** কপি করুন (একবারই দেখাবে)।
৩. R2 overview পাতার ডানে **Account ID** কপি করুন।
৪. Coolify-তে অ্যাপের Environment Variables-এ যোগ করুন:

| Variable               | মান                       |
| ---------------------- | ------------------------- |
| `R2_ACCOUNT_ID`        | Account ID                |
| `R2_BUCKET`            | `muti-uploads`            |
| `R2_ACCESS_KEY_ID`     | টোকেনের Access Key ID     |
| `R2_SECRET_ACCESS_KEY` | টোকেনের Secret Access Key |

চারটি থাকলেই অ্যাপ R2 ব্যবহার করে; না থাকলে নিচের volume-এ লেখে। Redeploy-এর পর
অ্যাডমিন ড্যাশবোর্ড খুলে দেখুন — লাল সতর্কবার্তা না থাকলে ঠিক আছে। এরপর লোগো ও
ছবিগুলো **আবার আপলোড** করুন (আগে সার্ভারে যা ছিল তা R2-তে যায়নি)।

### ৫খ. Persistent volume (R2 না নিলে)

অ্যাপের **Storages** ট্যাব → **+ Add** → **Volume Mount**:

| ফিল্ড            | মান            |
| ---------------- | -------------- |
| Name             | `muti-uploads` |
| Destination Path | `/app/uploads` |

> ⚠️ ভলিউম না থাকলে প্রতিবার নতুন ডিপ্লয়ে **সব আপলোড মুছে যাবে** — লোগো, ফেভিকন,
> হিরো ছবি, গ্যালারি, সব। কন্টেইনার চালুর লগে তখন `WARNING: /app/uploads is not a
mounted volume` দেখাবে, আর অ্যাডমিন ড্যাশবোর্ডে লাল সতর্কবার্তা।

## ৮. প্রথম ডিপ্লয়

**Deploy** চাপুন। লগ দেখুন — প্রথমবার ৫–১০ মিনিট লাগতে পারে।

ঠিকঠাক চললে লগের শেষে এই তিনটা লাইন দেখবেন:

```
==> Applying database migrations
==> Running seed
==> Starting Next.js
```

মাইগ্রেশন আর সিড **নিজে থেকেই** চলে — আপনাকে আলাদা করে কিছু চালাতে হবে না। সিডটা
বুদ্ধিমান: প্রতিবার শুধু অ্যাডমিন ইউজার আর সাইট সেটিংস আছে কি না দেখে, আর কোর্স-নোটিশ
তখনই বসায় যখন ডাটাবেস একদম খালি। তাই **রি-ডিপ্লয় করলে অফিস যা মুছেছে তা ফিরে আসে না**।

এখন `https://mutibd.com` খুলে দেখুন — HTTPS-এ সাইট আসার কথা।

## ৮ক. অ্যাডমিন প্যানেল আলাদা সাবডোমেইনে (সুপারিশ)

অ্যাডমিন প্যানেল ডিফল্টে `আপনার-ডোমেইন/admin`-এ থাকে। চাইলে সেটিকে নিজস্ব
সাবডোমেইনে সরানো যায়, যেমন **`ultrasound.muti.ac.bd`**। লাভ তিনটি:

- **সেশন কুকি আলাদা হয়ে যায়।** এখন লগইন কুকিটা পাবলিক সাইটের প্রতিটি পাতার
  রিকোয়েস্টের সাথেও যায়। আলাদা হোস্ট হলে কুকিটা শুধু অ্যাডমিন হোস্টেই যায়,
  পাবলিক সাইটের কোনো স্ক্রিপ্ট সেটি পড়তেও পারে না, ব্যবহারও করতে পারে না।
- অ্যাডমিন হোস্টে আলাদাভাবে **IP allowlist / Cloudflare Access / WAF** বসানো যায়,
  পাবলিক সাইট অচল না করেই।
- পাবলিক ডোমেইনে `/admin` আর সার্ভ হয় না।

### কীভাবে

১. **DNS**: Cloudflare-এ `ultrasound` নামে একটি A/CNAME রেকর্ড যোগ করুন, একই সার্ভারের দিকে (প্রক্সি কমলা মেঘ চালু)।
২. **Coolify → আপনার অ্যাপ → Domains**: পুরনো ডোমেইনের পাশে `https://ultrasound.muti.ac.bd` যোগ করুন। একই অ্যাপ দুটো ডোমেইনেই সার্ভ করবে, আলাদা ডিপ্লয় লাগবে না।
৩. **Environment variables**-এ যোগ করুন:

```
ADMIN_HOST="ultrasound.muti.ac.bd"
```

`NEXT_PUBLIC_SITE_URL` কিন্তু **পাবলিক ঠিকানাই** থাকবে — সনদ ও কার্ডের QR কোড
ওখান থেকেই তৈরি হয়।

৪. Redeploy দিন।

এরপর:

| ঠিকানা                           | কী হয়                                                    |
| -------------------------------- | --------------------------------------------------------- |
| `ultrasound.muti.ac.bd/`         | অ্যাডমিন ড্যাশবোর্ড                                       |
| `ultrasound.muti.ac.bd/login`    | লগইন পাতা                                                 |
| `ultrasound.muti.ac.bd/students` | শিক্ষার্থী তালিকা (পুরনো `/admin/students`-ও চলবে)        |
| `muti.ac.bd/admin`               | অ্যাডমিন হোস্টে পাঠিয়ে দেবে (পুরনো বুকমার্ক নষ্ট হয় না) |
| `muti.ac.bd/`                    | আগের মতোই পাবলিক সাইট                                     |

> **চাইলে আরও শক্ত করুন:** Cloudflare → `ultrasound` সাবডোমেইনে **Cloudflare Access**
> বসিয়ে দিন (শুধু অফিসের ইমেইলগুলো অনুমোদিত), অথবা অফিসের IP ছাড়া বাকি সব ব্লক করুন।
> তাহলে পাসওয়ার্ড ফাঁস হলেও বাইরে থেকে কেউ লগইন পাতাই দেখবে না।

`ADMIN_HOST` না দিলে আগের মতোই সব এক ডোমেইনে চলবে, কিছুই ভাঙবে না।

## ৮খ. ইমেইল: Brevo

ফর্মের নোটিফিকেশন, নমুনা অধ্যায়ের ডাউনলোড লিংক — সব ইমেইল Brevo দিয়ে যাবে।
SMTP-র চেয়ে ভালো: কোন মেইল পৌঁছেছে, কোনটা বাউন্স করেছে, কোনটা স্প্যামে গেছে —
Brevo-র ড্যাশবোর্ডে দেখা যায়।

১. Brevo-তে **Senders & domains** → `no-reply@muti.ac.bd` ঠিকানাটি যোগ করে verify করুন।
ডোমেইন verify করলে (SPF/DKIM রেকর্ড বসিয়ে) ডেলিভারি অনেক ভালো হয় — এটা করে নেওয়াই ভালো।
২. Environment variables-এ যোগ করুন:

```
BREVO_API_KEY="আপনার-কি"
MAIL_FROM="no-reply@muti.ac.bd"
MAIL_FROM_NAME="MUTI"
NOTIFY_EMAIL="office@muti.ac.bd"     # কোথায় নোটিফিকেশন যাবে
```

৩. Redeploy দিন, তারপর সাইট থেকে একটা টেস্ট আবেদন পাঠিয়ে Brevo → **Transactional → Logs**-এ দেখুন।

> API কি কখনো কোডে বা চ্যাটে লিখবেন না — শুধু Coolify-র environment variables-এ।
> কি ফাঁস হলে Brevo-তে গিয়ে সেটি মুছে নতুন একটি তৈরি করুন।

Brevo না দিলে SMTP ব্যবহার হবে, সেটাও না থাকলে মেইল শুধু লগে লেখা হবে —
আবেদন কখনো হারাবে না, কারণ ডেটাবেসে তো আগেই সেভ হয়ে গেছে।

## ৮গ. টু-ফ্যাক্টর অথেনটিকেশন (2FA)

পাসওয়ার্ডের সাথে ফোনের ছয় অঙ্কের কোড। **প্রতিটি অ্যাডমিন নিজের অ্যাকাউন্টে নিজে চালু করবেন**,
অন্য কেউ কারও হয়ে চালু করতে পারে না।

অ্যাডমিন প্যানেল → বাঁ মেনুর নিচে **Security** →

১. **Turn on** চাপুন
২. Google Authenticator / Microsoft Authenticator / Authy দিয়ে QR স্ক্যান করুন
(স্ক্যান না হলে "Cannot scan the code?" খুলে কি-টা হাতে লিখুন)
৩. অ্যাপের ছয় অঙ্কের কোড লিখে **Turn on**
৪. **১০টি ব্যাকআপ কোড** দেখাবে — প্রিন্ট করে বা লিখে রাখুন। **এগুলো আর দেখানো হবে না।**
ফোন হারালে এক একটি কোড দিয়ে একবার করে লগইন করা যাবে।

এরপর থেকে লগইনে ইমেইল+পাসওয়ার্ড দিলে কোড চাইবে।

**কেউ ফোন হারালে:** সুপার অ্যাডমিন → **Users** → ঐ ব্যবহারকারীর সারিতে লাল ঢাল আইকনে
চাপ দিয়ে 2FA মুছে দিন (কাজটি Activity log-এ লেখা থাকে), তারপর তিনি আবার সেট করবেন।

**অ্যাকাউন্ট লক:** পরপর ৮ বার ভুল চেষ্টায় অ্যাকাউন্ট ১৫ মিনিট লক হয়ে যায়।
সুপার অ্যাডমিন **Users** পাতা থেকে তালা খোলার আইকনে চাপ দিয়ে আগেই খুলে দিতে পারেন।

## ৮ঘ. SMS ও WhatsApp

শিক্ষার্থী ও রোগীর কাছে খুদে বার্তা পাঠানোর জন্য (ভর্তি নিশ্চিত, ক্লাস শুরুর আগে,
সিরিয়াল কনফার্ম, সনদ তৈরি)।

**গেটওয়ে না দিলেও কিছু হারায় না** — প্রতিটি বার্তা **Messages** পাতায় “not sent”
হিসেবে কারণসহ জমা থাকে, আর গেটওয়ের তথ্য বসানোর দিন থেকে বার্তা যেতে শুরু করে।

বাংলাদেশে যেকোনো রিসেলার থেকে একটি masking/sender ID নিতে হবে (BTRC অনুমোদিত)।
Environment variables-এ:

```
SMS_PROVIDER="bulksmsbd"      # অথবা sslwireless, অথবা generic
SMS_API_KEY="গেটওয়ের-কি"
SMS_SENDER_ID="MUTI"          # অনুমোদিত মাস্কিং নাম
```

`generic` নিলে রিসেলারের দেওয়া URL-টি হুবহু বসান, যেখানে যে মান বসবে সেখানে
`{key}`, `{number}`, `{sender}`, `{message}` লিখে দিন:

```
SMS_PROVIDER="generic"
SMS_API_URL="https://example.com/api?key={key}&to={number}&text={message}"
```

**WhatsApp**: Meta-র Cloud API যুক্ত করতে চাইলে `WHATSAPP_TOKEN` ও
`WHATSAPP_PHONE_ID` দিন। একটা কথা পরিষ্কার করে বলা দরকার — Meta শুধু তখনই
ফ্রি-টেক্সট বার্তা পৌঁছে দেয় যখন ঐ ব্যক্তি গত ২৪ ঘণ্টার মধ্যে আপনাকে মেসেজ করেছেন;
এর বাইরে আগে থেকে অনুমোদিত টেমপ্লেট লাগে। তাই সাধারণ কাজের জন্য সাইটের
click-to-chat লিংকই (যেগুলো এখনই আছে) সবচেয়ে নির্ভরযোগ্য, আর জরুরি ঘোষণার জন্য SMS।

বার্তার লেখা বদলানো যায় অ্যাডমিন → **Message templates** থেকে, কোনো ডেভেলপার ছাড়াই।

## ৮ঙ. প্রতিদিনের অটোমেটিক রিমাইন্ডার

দুটি রিমাইন্ডার নিজে থেকে যায়: ক্লাস শুরুর **৩ দিন আগে** ব্যাচের শিক্ষার্থীদের,
আর **আগামীকালের** নিশ্চিত হেলথ সিরিয়ালের রোগীদের।

Coolify → আপনার অ্যাপ → **Scheduled tasks** → নতুন টাস্ক:

```
schedule: 0 9 * * *
command: curl -fsS -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/cron/messages
```

`CRON_SECRET` না থাকলে environment variables-এ একটা লম্বা এলোমেলো লেখা বসান
(হেলথ ডেটা মুছে ফেলার কাজটিও এই একই কি ব্যবহার করে)।

দিনে একাধিকবার চললেও সমস্যা নেই: একই বার্তা দ্বিতীয়বার যায় না।

## ৯. Cloudflare প্রক্সি চালু করা

সাইট HTTPS-এ আসার পর (অর্থাৎ Let's Encrypt সার্টিফিকেট পাওয়া হয়ে গেছে):

১. Cloudflare → **SSL/TLS** → encryption mode **Full (strict)** করুন।
❌ **Flexible করবেন না** — রিডাইরেক্ট লুপ হবে।

২. Cloudflare → **DNS** → দুটো A রেকর্ডের মেঘ **কমলা (Proxied)** করে দিন।

৩. Cloudflare → **SSL/TLS → Edge Certificates** → **Always Use HTTPS** চালু করুন।

৪. Cloudflare → **Speed → Optimization** → **Rocket Loader বন্ধ রাখুন**।

> Rocket Loader জাভাস্ক্রিপ্ট লোডের ক্রম বদলে দেয়, এতে Next.js-এর হাইড্রেশন ভাঙে —
> মোবাইল মেনু, ফর্ম, সিট কাউন্টার কাজ করা বন্ধ করে দিতে পারে।

## ১১. ব্যাকআপ (অবশ্যই সেট করুন)

Coolify-র Postgres সার্ভিসে **Backups** ট্যাব আছে:

১. **+ Add backup** → schedule `0 3 * * *` (প্রতিদিন রাত ৩টা)।
২. **Number of backups to keep: 14** (স্পেক অনুযায়ী)।
৩. সম্ভব হলে একটা S3 বাকেট যুক্ত করুন — শুধু একই সার্ভারে ব্যাকআপ রাখলে সার্ভার
নষ্ট হলে ব্যাকআপও হারাবে।

**আপলোড ভলিউমের ব্যাকআপ আলাদা।** ডাটাবেস ব্যাকআপে ছবিগুলো থাকে না। সার্ভারে
একটা ক্রন রাখুন:

```sh
tar czf /backups/uploads-$(date +%F).tar.gz /var/lib/docker/volumes/<volume-name>/_data
```

| অ্যাডমিন সাবডোমেইনে লগইনের পর আবার লগইন পাতায় ফেরত আসে | `ADMIN_HOST`-এ ঠিক হোস্টনামটি আছে কিনা দেখুন (পোর্ট বা `https://` ছাড়া, শুধু `ultrasound.muti.ac.bd`), আর Coolify-তে ডোমেইনটি অ্যাপে যোগ করা আছে কিনা। |

| অ্যাডমিনে লগইন হয় না / সাথে সাথে লগআউট                 | `AUTH_SECRET` বদলে গেছে, অথবা `AUTH_URL` আসল ডোমেইনের সাথে মেলে না। দুটো ঠিক করে রি-ডিপ্লয় করুন।                                                       |
| আবেদন জমা হয় কিন্তু ইমেইল আসে না                       | `SMTP_PASS` খালি বা ভুল। Gmail-এর **App Password** লাগবে, সাধারণ পাসওয়ার্ড নয়। আবেদনগুলো কিন্তু অ্যাডমিনে জমা থাকছে।                                  |
